# IR、经验记忆与后续探索：论文审查和执行建议

日期：2026-09-10。性质：本地源码、论文文本、证据记录审查，以及相关原始论文调研；不是新 GPU 性能实验。本文提出的组织方式和实验尚未实现。未修改旧证据、主论文或搜索代码。

**核心判断：应积累“带条件的观察、可检验的机制和明确权限的行动建议”。程序 IR 描述实现，证据记录描述实验，知识记录描述可以从实验推出什么。三者相连，但不能混成一条胜负结论。**

**一、先校正这次复盘的前提。**

HMMA 和 tcgen05 都有探索，不能断言历史资源一定偏向哪一边，因为没有完整配平账本。能确认的是：两边起点、路径覆盖、索引可见性和正式比较不对称。强化 HMMA 已存在，但未进入最新九形状 CAKE/官方正式比较；本轮路径索引也没有把完整强化 HMMA 作为独立路径。因此，“经验可能不一致”目前首先是需要审计的知识覆盖问题，不是已经证明 IR 导致了某个性能损失。

当前论文 `main.tex` 的主要实证是 CAKE-generated B300 路线内的 cpc 优化、机制定位和前瞻插值；它明确没有证明跨设备迁移或多 agent 优势。SM100 交接又包含后续官方/CAKE 对照。两批材料的时间、范围和问题不同，不能用后者替前者补写未经实验的“知识可迁移”主张。[L1][L2]

**二、值得保留的基础。**

- 开放协议允许改变算法、阶段、布局、驻留和分工，并明确“当前 IR 不支持不是算法失败”。这是下一轮的正确入口。[L3]
- `MigrationFailureCard` 已记录具体条件、不可外推范围、重新打开条件；`MigrationKnowledgeClaim` 已区分观察、机制和使用方式。应补齐语义与连接，不需要推倒重建。[L4][L5]
- 正式性能已转为隔离进程；旧结果保留并标记用途失效。后续需要把这些状态传递到依赖它们的结论与摘要。[L2]
- 论文中的 resident-grid-capacity 规则不是单纯记住 cpc9：它使用工作量、SM 数和资源限制，并做了方向相反的前瞻预测。这正是值得保留的经验总结方式。不过适用域仍是该编译配置中的已测条件。[L1]

**三、实际发现的问题与边界。**

| 发现 | 风险 | 最小改进 |
|---|---|---|
| 本轮路径索引未独立列出强化 HMMA | 新 agent 可能只检索到官方 HMMA 与失败 H3 | 补齐强化 HMMA 的源码、构建、guard、证据和复测状态 |
| 通用 `Conclusion` 只有轮次、profile、candidate、状态、文本和证据引用 | 没有一等字段表达机制适用条件、比较对象、测量版本和行动权限 | 让摘要引用结构化 claim，并携带必要条件与未知项 |
| CAKE 被标成 scoped direct-swap 命题的 `observed_refute` | 混淆“反驳当前命题”与“反驳不当外推” | 拆成两个命题；让关系明确指向被挑战的命题 |
| 知识校验把静态拒绝、支持和反驳都计入 resolved families | “做过两个挑战”可能被误作“已得到可复用支持” | 按证据性质与命题方向验证；挑战次数仅表示覆盖 |
| 因果成熟度仅要求剩一个机制字符串；transfer 标签未要求目标域证据 | 字段合法不等于因果或迁移成立 | 分别记录干预设计、未排除解释、来源域与目标域结果 |
| 只禁止 performance decision 变为 verifier rule | mechanism hypothesis 仍可能通过这种标签组合 | verifier rule 仅接受有明确依据、作用域的硬约束 |
| 失败卡的 compile/correctness/resource 状态也要求正 speedup | 诱导给没有有效计时的失败填写无意义数值 | 计时可空；只在正确、可比较的性能记录中定义 speedup |
| 通用候选 ID 只由当前 Schedule 字段生成 | 开放原型中，未进入 schema 的源代码差异可能失去身份 | 分开语义身份、物理设计身份、构建身份和实验身份 |

针对知识校验做了两个不写入知识库的合成输入检查：①两个只有反驳、没有证据引用的挑战，搭配 `TRANSFER_VALIDATED/REUSABLE_MECHANISM`；②`MECHANISM_HYPOTHESIS/VERIFIER_RULE`。当前函数均返回空诊断。这证明标签校验存在缺口；**不证明已有记录已发生错误自动晋级或生产部署**。[L4]

另一个需要避免的误判：`evolve.py` 计算了资源 Pareto frontier，但当前协调器使用的是全部 accepted 候选；不能把这个 frontier 直接说成已经造成 ValueSlice 被剪枝。未来若用资源前沿淘汰候选，要注意更少切片、更少资源和更多 occupancy 都不是单调的性能定理。[L6]

**四、组织上采用六类小记录，先用现有 JSON 和索引，不建设新数据库。**

| 记录 | 回答什么 | 应保留的关键内容 |
|---|---|---|
| Contract | 在算什么，什么算正确 | 运算、形状/序列分布、初态/终态、dtype、舍入要求、oracle与阈值版本 |
| Implementation | 怎么算，哪份实现 | backend、算法与阶段、数据位置、布局、工作分工、同步/流水、源码/构建身份、已知与未知字段 |
| Observation | 在什么条件下观察到什么 | 双方实现、输入身份、scope、硬件/工具链、测量协议、原始样本与独立单位、误差/时间/区间、有效性 |
| Claim | 这条证据支持哪一句话 | 精确命题、条件、支持/反驳/未决证据、替代解释、已验证范围、需要复验的变化 |
| Decision | 当时为什么采取某个动作 | continue/deprioritize/stop/deploy、引用claim、预算和目标、决策日期、重开条件 |
| Campaign | 怎么得到这些候选 | 起始资产、搜索空间与版本、预算、共享知识、候选来源、拒绝/未测原因、检索与选中记录 |

关键关系是：实验使用具体实现，结论引用实验，决策引用结论；一个实验可以支持多条不同范围的命题。`derived_from` 不能同时表示“代码继承”“受其启发”和“拿它当基线”，应区分这三种关系。

例如 CAKE 与官方可以具有 `compares_against` 关系；若没有源码继承证据，不应仅凭同一运算把它当成官方的代码子节点。W3C PROV 的实体、活动和来源关系可供借鉴，但不需要引入整套 RDF 基础设施。[R5]

**五、每条经验用同一段话总结，正结果和负结果都这样写。**

> 在【已验证条件】下，把【实现A】改为【实现B】，观察到【完整scope的变化及不确定性】。这支持【精确命题】；【机制解释】目前为观察/假说/干预证据。预计需要保持【迁移前提】。当【关键条件变化】时重新验证。下一步最便宜的验证是【实验】。它可以影响【优先级/复测/部署】，不能推出【外推边界】。

注意区分“实验中固定了什么”和“迁移时必须固定什么”。前者是事实；后者也是一个需要证据的判断。例如某次只测 H12，不足以证明只有 H12 才有该机制，也不足以授权 H96 直接使用参数。

三条实际重写示例：

**ValueSlice。** 在历史 H12、单序列的测量中，V16 切片扩大独立 CTA 数，完整 forward 降时约27%。这证明该条件下切片有价值；对 underfill 的解释受到工作划分与计时支持，但复制输入请求、资源和调度也随之改变。迁移到别的路线时，复用“寻找独立工作、核算复制成本”的假说；不要复用“V16 必胜”或固定27%。H96、packed、多流和新资源占用是需要复验的条件。

**tcgen05 direct。** 在 B300、Phase6、V128、grid12、inner64、L0 条件下，候选为0.919742×。当前相同候选不值得无变化重测。TMEM协议、readback与延迟隐藏仍是竞争解释；不能记录成已证明 TMEM allocation 是唯一原因。薄N、跨阶段驻留、布局与协议变化可重新打开。

**resident-grid-capacity。** 在论文所绑定的 prepare/chain 实现与资源配置上，容量规则成功预测了新的工作量点，证据强于“cpc9有效”。但换成 HMMA recurrence 或改变工作划分，可能连 grid 公式都不相同；先重新推导对应关系和资源限制，再校准、验证，不能只把实测R替换后宣布规则仍成立。

**六、经验晋级不应只有一条成熟度阶梯。**

建议分开记录四个维度：

1. 实验有效性：有效、只用于诊断、被替代、未知。
2. 重复与覆盖：同进程重复、独立进程、不同输入、不同形状、不同设备；这些不是同一种重复。
3. 机制支持：相关观察、阶段定位、受控干预、仍有混杂；不要因为只写了一种解释就宣布因果。
4. 迁移支持：来源域、目标域、映射假说、目标域验证结果。目标域未测就写未测。

合法性与性能权限另行判断：证明候选非法可以拒绝它；历史变慢只能影响排序和预算，不能获得无限期全局禁令。经过多域验证的性能规则仍然是经验规则。

广义命题“所有迁移都无收益”可以被一个有效正例反驳；窄命题“此V128直接替换在这个条件下较慢”与CAKE较快并不矛盾。应为它们建立不同claim，并把CAKE连接到广义命题的反驳边，不撤销窄命题的原观察。[L5]

**七、跨 HMMA/tcgen05 检索采用分层降级。**

- 条件与实现匹配：取回原候选、实验和行动建议；可复用已有结果，但注意测量环境与目标是否改变。
- 物理前提相近：取回机制卡，列出哪些前提匹配、哪些未知，作为优先验证的候选。
- 只有算法相同或描述相似：取回设计启发，不继承性能数字、停止决定或部署权限。

默认检索同时给出相关正例、负例、关键反例和最强已有竞争基线，不只取一个文本最相似的winner。对源于同一实验的多份报告去重，避免把复述误当独立支持。

未知字段不能当通配符。源码和二进制hash用于确认是否同一个实验对象，物理特征用于判断机制是否相近；不能用hash不同禁止一切启发，也不能用特征相近合并原始计时。

对于被替代的同进程测量，只让依赖该测量幅度的claim失效；源码事实或仍有效的正确性证据不应一并删除。摘要应在检索时检查上游状态，避免旧结论永久留在prompt里。

每次agent决策留一条短记录：检索了哪些claim、用于哪项决定、哪些条件不匹配、为什么仍测试或不测试。只记录可检查的依据与动作，不记录私密推理过程。

**八、相关研究给出的启示及本项目的潜在贡献。**

- Ansor以层级搜索空间扩大结构覆盖，再优化候选。对本项目的启示是同时保留结构变化和局部参数搜索；本文据此提出的经验权限设计，不是Ansor已验证的结论。[R1]
- TensorIR将张量计算原语放入编译表示。它支持我们把程序的计算/物理结构表达清楚，但“程序可表达、可检查”不能替代“性能解释正确”。[R2]
- MetaSchedule强调模块化扩展搜索空间。适合借鉴为 `needs_extension` 的出口，而不是要求所有新方案先符合固定旧模板。[R3]
- Learning to Optimize Tensor Programs使用统计成本模型指导搜索并研究跨workload迁移。可迁移表示用于加速寻找好候选，不等于迁移原参数或保证其最优；本项目应同样把迁移作用落实为可检验的搜索帮助。[R4]

这些研究已经覆盖IR、自动调优、可扩展搜索和迁移等方向。“用了JSON/typed IR/记忆”本身不足以构成强论文新意。更有价值且尚待验证的主张是：**条件明确、允许反驳和修订的经验组织，能减少跨实现路线的错误外推，并在固定预算下帮助agent更快找到可靠候选。**这必须通过方法对照实验建立，不能由CAKE的加速结果代替。

**九、论文证据拆成三个问题，分别回答。**

| 问题 | 当前支持 | 下一步证据 |
|---|---|---|
| SM100迁移在工程上是否值得 | CAKE相对当前官方的已测正收益 | 强化HMMA与CAKE统一复测；然后对等追加预算 |
| 有条件的物理规则能否预测新profile | cpc规则的窄域前瞻验证 | 对新编译配置/路线重新提出迁移假说并验证 |
| 新经验组织是否改善agent搜索 | 有表示与校验原型，尚无对应搜索优势对照 | 无历史性能经验、普通摘要、有条件经验三组对照 |

原论文可继续保留其窄域实证，不应把CAKE胜官方直接改写成“IR记忆有效”或“agent学到了可跨ISA规律”。“proof-carrying”应明确指哪类可检查证据；IR检查、来源链和置信区间不是任意语义正确性或因果解释的形式化证明。

**十、最小方法验证设计。**

先做离线审计，再选择少量真实搜索，避免重建巨大框架。

离线层：选取历史经验，按时间截断资料，让总结器在当时已知信息下给出经验；用后续已发生的结果检查其外推。历史回放只能评估记录与判断，不能证明它在未知搜索空间里发现了新winner。统计错误硬拒绝、证据方向错误、scope缺失、无效证据被沿用，以及应降级却直接迁移的次数。

在线层：三个实验组共享同一语义要求、工具、初始实现、搜索空间与硬约束；差别仅在历史性能知识的呈现与使用。

- A：不提供历史性能经验，但保留公共硬件事实、API和正确性要求。
- B：提供相同历史资料的普通结论摘要。
- C：提供有条件、带反例和重开条件的结构化经验。

比较B/C时控制历史证据内容、上下文上限和检索开销，不能让C偷偷得到更多源码、算力或更强初始实现。候选筛选、失败调试和知识处理计入预算，最终评估另行预留相同资源。

目标任务分别覆盖同路线新形状、同ISA新布局和跨HMMA/tcgen05路线。双向迁移分别报告。目标任务的后验总结与衍生文档不得进入输入；已见过的九形状只能用于开发，不能重新标成未知held-out。

主要指标为固定预算下最佳已验证public-full性能，以及达到预先确定目标所需成本。辅助指标包括有效候选比例、重复无效试验、被错误排除的已知可行候选、候选结构覆盖和知识处理开销。所谓错误剪枝率必须说明分母是审计候选池，不是未知的完整搜索空间。

用多个独立搜索轨迹估计方法波动；不要把同一个kernel的几百次计时当成几百次agent实验。若C在某些目标上差于A/B，应报告负迁移，而不是只汇报成功转移。

**十一、落地顺序与完成标准。**

1. **整理资产。** 补强化HMMA路径；核查证据链接与被替代状态；把窄/广命题拆开。完成标准：每条主结论都能定位有效实验与确切比较对象。
2. **修正经验语义。** 扩展现有claim和摘要接口，修补已发现的标签校验缺口；失败无有效性能时用空值。完成标准：反驳不会提升原命题的支持，目标域未测不会被标为已迁移。
3. **做已有强者的统一复测。** 先建立真实性能差距，再分配对等追加探索预算。完成标准：每个形状知道真实route和fallback，而非只知道backend名称。
4. **验证经验帮助。** 先做离线审计，再做小规模A/B/C真实搜索。完成标准：能区分更好的检索、更多预算和方法本身的贡献。
5. **按结果更新论文。** 若只证明可审计和少误用，就写这些；若固定预算搜索更好，再写效率收益；若跨路线失败，保留反例并收窄范围。

不建议现在建设通用知识图谱服务、为每次阅读增加哈希流程、强制所有idea完整类型化，或先做多agent涌现消融。优先把现有记录变成可正确使用的少量经验，并验证它们是否真的帮助下一次探索。

**十二、B300 小范围验证结果。**

随后在 B300 上执行了两轮三形状探索性验证。每个测量进程只加载一个实现，使用 cold-L2 CUPTI、4个平衡顺序block、每block 10次warmup和40次测量；测试非零BF16初态，计入每次调用的数据变换与状态写回。该实验复用了已有官方、强化HMMA和CAKE二进制，不是新的等预算搜索。[结果摘要](evidence/b300_ir_knowledge_smoke_summary.json)

- H12 fixed8192：强化HMMA自动选择V16和预取路径，相对官方为1.833x；在历史CAKE peer正确性契约下，CAKE相对强化HMMA仍为1.530x。
- H12 packed 8x1024：强化HMMA自动回退V128，与官方基本相同；强制V16约慢1.94x；CAKE相对强化HMMA为2.682x。
- H96 fixed8192：强化HMMA自动回退V128，相对官方约1.010x；强制V16约慢2.22x；CAKE相对强化HMMA为2.391x。
- 强化HMMA在三形状的output和final state均与官方逐位一致。CAKE三形状均通过历史 `atol=rtol=0.01` peer gate；如果改用本轮额外定义的relative-L2和normalized-Linf均不超过1%的严格gate，两个H12形状失败、H96通过。两套数值标准回答不同契约，不能混写。

这批结果支持本文的组织建议：成功经验必须保留profile和数值契约；强化HMMA是实质竞争基线，不能从索引中缺席；一个形状的V16 winner不能跨形状成为默认规则。同时，CAKE在这三个历史契约形状上仍胜过强化HMMA。它没有验证“结构化经验能提高agent搜索效率”，该主张仍需要第十节的A/B/C方法实验。
