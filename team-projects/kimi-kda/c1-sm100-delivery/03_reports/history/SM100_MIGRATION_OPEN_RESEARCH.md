# FlashKDA 官方 kernel 当前使用 SM80 MMA，分析迁移到 SM100 是否值得

## 当前判断

后续交付安排已明确：以带证据的多路径 Typed IR 集合、路径比较及成败复盘作为主线回答中的正式结果；在形成迁移问题的阶段性答案后，再开展并发等此前论文中的挑战。本文 H1–H8 仍是待验证种子，不因加入结果结构就变成已实现路径。具体推进与结果要求见 [最新交接](HANDOFF_SM100_OPEN_RESEARCH.md)。

已有证据支持继续研究迁移，并已证明部分完整 SM100 实现在特定条件下有收益；尚不能据此认定任何一种局部迁移都值得，也不能将一个指令替换的失败推广为迁移方向的失败。研究问题保持标题原文。CHUNK16、P3/P4、V16、跨阶段驻留、并行度、Typed IR 和多 agent 都是可选择的研究手段，不是题目的附加条件。

本次完成的是源码审计、上下游资料调研、候选推导和多 agent 方法设计，没有新增 GPU 性能或正确性结果。资料核查截至 2026-09-10。作业官方快照按题面记录为 `1ce47ea3bb22c84eb9cc665028399cf35e8ffb0b`；在线 master/main 只用于调研线索，后续实验必须另行记录实际版本。当前在线 PTX 文档显示 ISA 9.4，不能默认本地 CUDA 13.0 已支持其全部能力。

## 1. 现有证据究竟回答了什么

| 证据 | 能支持的判断 | 不能支持的判断 |
|---|---|---|
| 官方 benchmark、SASS、NCU | 题面所述 HMMA 计算路径已复现；可定位实际执行特征 | “旧指令必然落后”或“新指令必然有益” |
| V128/grid12 Phase-6，inner64/L0 为 0.919742× | 该指令替换在所测条件下更慢 | 所有 phase、形状、算法、SM100 实现都更慢 |
| B300 job 24111，V16/grid96 inner64：L0 1.615021×，L1 0.778523× | 原生布局计算有潜力，当前标量表示转换消耗了收益 | 已加速完整 FlashKDA；所有转换方案都不划算 |
| 本地 CAKE 对官方六个 H12 profile：2.126–3.397×，几何平均 2.655× | 存在通过该正确性检查的有益完整 SM100 路径 | 这些收益全部来自 tcgen05；候选已超过优化 HMMA |
| ValueSlice 和预取结果 | 提供另一种改善和强 HMMA 比较对象 | 证明 MMA 迁移成功 |

这些数据来自已存证实验，见 [1]–[4]。尤其是 `0.328 μs/phase`，只是 job 24111 那个 L1 实现相对其 HMMA 对照的差距，不应变成所有新算法必须跨越的统一门槛。

报告中还有一处必须纠正的推论：原最终报告 4.1 将“只换指令、大 CHUNK + rescale”概括为已被否决；但同报告 3.1 已记录 FLA safe/block C32/C64 路径 finite。因此被否决的是机械扩大常量的路径，而非稳定的大块算法这一族。[2]

## 2. 官方设计选择与真正的正确性要求

官方文档将 CHUNK16 解释为数值范围、小矩阵求逆成本和 SM80 适配的综合取舍。K1/K2 的边界来自当时融合实现的测量；K2 还利用寄存器转置优化阶段衔接。这些事实说明现实现经过认真优化，也说明迁移应允许重新检验其选择。[5]

### 必须保持的对象

输入所代表的 KDA 运算、gate/beta/归一化含义、输出、初始及最终状态、变长序列边界，构成共同的比较对象。不能通过改 gate 下界、减少 token、忽略状态、移动计时范围或挑选较容易的数据制造收益。上游/下游适配如有新增工作，也应计入相应总成本。

### 应明确区分的两种数值目标

**官方位级兼容路线：** 保持当前舍入及状态更新方式，对官方逐位一致测试负责。适合精确指令/布局迁移，便于隔离机制。

**算法等价路线：** 允许改变分块、求解、内部精度和舍入位置，但必须预先指定参考、误差指标与阈值，并验证输出和最终状态。它不冒充官方 bitwise 兼容。题目明确允许“大 CHUNK + rescale”，因此应保留这一研究入口。[6]

两条路线都不允许候选看到失败后再放宽阈值。大块或仿射重写还需长序列、强衰减、非零初态、tail/packed、连续调用状态等测试；只测 finite 不足以验证等价。

现有 IR 并非处处锁死 CHUNK16：`mma_migration.py:304–308` 只对 instruction-only 作这一要求；真正把 CHUNK16、舍入 DAG 固定为全局条件的是某次 Stage 11 实验协议。必须保留这次实验的历史含义，同时允许其他实验另立问题与条件。

## 3. 上下游调研带来的研究入口

### 3.1 上游算法与参考实现

Kimi Linear 论文提供了 KDA 的算法背景；FLA 参考提供了与当前 FlashKDA 阶段组织不同的表达。可从参考递推和 chunk 公式出发，重新决定什么先算、什么与状态有关、什么适合矩阵乘。这里借用的是可核对的数学结构，不将其他模型或论文的吞吐直接套用到本作业。[7][8]

本地 `fla_kda_ref/chunk_intra.py:65–75` 描述了子块构造及合并求解；`naive.py:127–160` 则提供相对门控与预计算中间量的线索。它们使“大块只能用整块朴素 Neumann 幂”的假设不再成立。[8]

### 3.2 SM100 指令与编程系统

PTX、CUTLASS 和 Triton/Gluon 示例可用于核实实际支持的 tile、存储及同步方式。Gluon 的 tcgen05 示例明确区分：累加器在 TMEM，左操作数可来自 SMEM 或 TMEM，右操作数来自 SMEM。这提示布局方向属于设计变量；TMEM 不能被当作可任意进行标量算术的普通存储。[9]–[11]

每个新机制都应通过目标 SM103a 的编译和 lane 正确性检查。文档支持、编译器支持、IR 支持、实际提速是四个不同问题。CUTLASS 某个 kernel 模板支持的 tile 集，也不能直接当作整个 ISA 的合法 tile 集。

### 3.3 下游现成实现与公共入口

FlashInfer PR #4262 已合入 CAKE 生成的 SM100a KDA prefill，公开的 B200 六形状比较报告几何平均 2.0512×，并给出 public API、状态与比较条件。这是重要实现来源；其 B200 条件不同于本地 B300 测量，不能混合计算。[12]

因此可以同时做两件事：从官方实现逐步迁移；从已正确且快的 SM100 实现反向拆解。前者寻找改动收益，后者寻找完整方案中必要的组成部分。反向拆解不要求先把 CAKE 的每个改动都装回官方结构，也不预设所有贡献可以分离。

CAKE 论文的方法启发是让候选所需能力反过来推动 IR 扩展。当前 IR 无法表达一个方案，应记录为表示能力缺口，而不是性能或数学否定。这是方法借鉴，不是本项目已经取得多 agent 优势的证据。[13]

## 4. 可以立即展开的假设

下列是首轮种子，全部为待验证方案；不是新白名单，agent 可以提出其他方案、合并它们或指出其不可行。

### H1：合并共享 state 的双投影

官方 P1 计算 `K_d S` 与 `Q_d S`，其中 `K_d,Q_d` 是 `[C,D]`，`S` 按逻辑取 `[D,V]`。两次乘法共享状态，已有 HMMA 实现也共享状态读取。[14]

可用恒等式：

```text
X = [K_d; Q_d]            # [2C,D]
Y^T = S^T X^T            # [V,D] @ [D,2C]
```

在 C16、D128、V128 时，得到 `[128,128] @ [128,32]`。这让两个相依流程共同需要的投影成为一个较宽的逻辑 GEMM；映射为多条合法指令，不能声称它天然是一条指令。

**最小实验：** 比较已有共享 state 加载的 HMMA 双投影与 tcgen05 拼接投影，计入拼接、描述符、同步、拆分与各自舍入。若节省不了协议或数据成本，就放弃该具体实现；不能用两个各自重复加载状态的弱 HMMA 对照夸大收益。

### H2：P4 输出与 P6 状态增量共同消费 U

源码 P4 使用 `Mqk @ U`，P6 使用 `K_r^T @ U`。这里 `U` 必须指 P3 舍入后的同一份 BF16 数据。两者并不依赖彼此的结果。[14]

由水平拼接可得：

```text
U^T @ [Mqk^T | K_r]
    = [(Mqk @ U)^T | (K_r^T @ U)^T]
```

C16、V128、D128 下是 `[128,16] @ [16,144]`。候选可以在共享 U 的一次逻辑计算中产生两个输出区域；具体使用 144、padding 到其他宽度或分成若干指令，要由合法性和总成本选择，不预设最优。

**最小实验：** 输入同一 U，对输出部分保留原 BF16 cast/add，对状态部分保留原 FP32 gate/FMA/BF16 更新。测完整两分支消费成本，并检查下一 chunk 所见状态。合并计算不等于合并数值后处理；不能把原有两个舍入后的加法偷偷改为一次 FP32 累加。

### H3：重设 K1/K2 分界，预先计算状态无关项

忽略舍入、只在实数代数层面，令 `A` 为局部逆，`B=diag(beta)`，则：

```text
U = A B (V - K_d S)
  = (A B V) - (A B K_d) S
```

右边两个括号可以在递推前计算；FLA 的参考表达也提供了预计算 W/U 的路线。[8] 这可能减少递推中的串行小 GEMM，让剩余状态乘法更适合 SM100。

**最小实验：** 先建立两种公式的数值对照，不能跨 BF16 舍入直接声称相等；再比较准备、workspace 写读、递推的合计。若只是把 K2 的时间搬到 K1，不能算收益。分别实现匹配 HMMA 与 tcgen05 版本，以区分算法收益与 SM100 增量。

### H4：大 CHUNK + 稳定表示 + 分块求解

重新探索 C32/C64 等，而不把候选限定为这些枚举值。数值处理可用局部指数重基准、相对 gate、子块求解等路线。以二分块下三角矩阵为例，实数恒等式是：

```text
L = [ L11   0  ]        L^-1 = [ L11^-1                    0     ]
    [ L21  L22 ]               [ -L22^-1 L21 L11^-1      L22^-1 ]
```

它说明大块逆不必直接沿用整块密集幂。两种表示都可能有额外开销；不能仅凭恒等式认定更便宜或更稳定。[8]

**最小实验：** 数值模型先比较一个 C32 与两个 C16 的完整运算；覆盖强衰减和非零初态。再测预处理、求解、状态更新总时间。重标定不是改 gate 定义或裁剪输入，也不是保证原 bitwise 路径不变。

### H5：数值块与物理调度块分开选择

保留每个局部 C16 问题，尝试将 K1 多个独立问题共同调度、共享协议或使用合法批处理结构。K2 仍可按原序递推。还可以保留小矩阵求逆的 HMMA，仅迁移 K1 构造或部分 K2 乘法。[5][14]

**最小实验：** 先验证批间隔离，再比较含打包、填零、拆包的完整准备路径。不同 chunk/head 有不同操作数，直接拼成稠密 GEMM 可能产生无用交叉项甚至错误结果；必须明确 block-diagonal 或其他隔离映射及实际有效 FLOPs。不能把额外无用运算包装成高吞吐。

### H6：从生产者到消费者共同选择表示

当前 V16 L1 在消费者端补做标量重排。可以让 K1 直接产出后续 SM100 所需格式，也可以在 K2 内保留多份适用于不同消费者的表示、选择性重算便宜中间量。选择标准是完整链的成本，而不是一味要求所有东西都放进 TMEM。[3][14]

**最小实验：** 一份原布局、生产者预排布局、必要时双布局或重算三个候选，统计真实写读字节和 K1+K2 总时间。输入准备不能挪出比较范围。更早形成布局也可能增加 workspace、寄存器或同步成本。

### H7：跨 chunk 流水与选择性指令迁移

把依赖图分成需要当前 state 的部分，以及下一 chunk 中可以提前做的门控、加载、描述符或局部准备。在当前异步 MMA 运行时推进后者，允许部分阶段用 HMMA、部分用 tcgen05、标量操作继续用 CUDA core。

**最小实验：** 从两 chunk 开始测实际重叠和资源占用，再延长到完整递推。不能提前执行真正依赖新 state 的计算，也不能假设 HMMA/tcgen05 拥有互不竞争的 Tensor Core 资源。若双缓冲降低驻留或延长关键依赖，可能反而更慢。[9][14]

### H8：用仿射段摘要挑战既有递推组织

参考递推在实数下可写为 `S' = A S + B`，两段组合为 `(A2 A1, A2 B1+B2)`。这提供了较大胆的算法入口：小段摘要、低秩表示或有限的分层组合，是否让 SM100 大矩阵计算足以补偿额外工作？[8]

**最小实验：** 先对 2/4 段计算摘要大小、有效运算量和舍入误差，再做一个两段组合探针。显式 D×D 摘要可能非常昂贵，浮点和中间 BF16 舍入也会破坏严格结合性。若成本模型已明显不利，可结束该表示方案，不必先实现完整 scan。

## 5. 多 agent 应怎样产生新方案

### 5.1 限制在哪里

`STAGE9_AGENT_PROTOCOL.md:7–22` 将任务限定为固定 prepare 路线的 CPC 决策树；`run_stage9_agents.py:212,255` 禁止工具/源码访问；`stage9_policy.py` 的动作主要是 CPC。这样的 agent 无法研究新算法与 ISA。

`stage11_causal_ladder.py:100–125` 只接受 lifecycle 与 thin_n 的完整 2×2；后续规则要求父方案冻结后才组合。这对那次因果确认有意义，但不能用来判断所有新提案是否可研究。`mma_migration.py` 当前也以 site 对应 instruction/tile、identity/transpose 等模型为主，不能自然覆盖跨 site 融合和复杂分解。[15]

过去四个 proposal 只有一个语义策略、强制多样性仍无新赢家，说明已运行的语法内搜索没有收益，不能证明迁移空间已穷尽。[16]

### 5.2 开放研究层与执行验证层分开

研究层接收公式、源码位置、草图、伪代码、反例和最小实验。不要要求 idea 一出现就符合旧 IR。每项只需说明真实改动、依据、收益机制、额外成本、数值影响和最便宜的证伪方式。

执行层仍检查真实 ISA、内存安全、异步协议、正确性和测量。没有现成 lowering 时，允许小范围 CUDA/CuTe/Triton 原型或按实际需要扩展 IR。它不会因此自动通过验证。

状态应明确分为 `idea`、`needs_ir_extension`、`compile_failed`、`correctness_failed`、`correct_unmeasured`、`measured_gain/regression/inconclusive`。IR 不支持、编译器不支持和数学错误不可合并为同一种拒绝。

### 5.3 具体运行方式

首轮三个独立入口：官方算法与源码；SM100 与可运行实现；上下游接口和全流程成本。入口只是资料分工，每个 agent 都可提出完整方案，不限定它只能改某个参数。主 agent 核查来源和冲突，不预设获胜机制。

初稿后交换事实、代码片段、公式、假设和不确定性，并标明成熟度。长期可信知识仍只接纳经过验证的结论，但临时研究区必须允许未验证 idea 相互启发。无需交换私密推理轨迹。

第二轮换位批评：检查别人的最强方案缺少什么，再尝试结合另一份方案产生新设计。合成可以先于父方案实现；如果之后要声称组合增益，才需要对应测量。若父设计无法独立运行，应诚实称为联合设计结果，不捏造可加交互效应。

例如，H3 先改变代数分界，H1 再把多个共享 state 的乘法拼接，可能形成“预计算状态无关项 + 一次较宽状态乘法”的联合方案。这不是两个现成补丁相加，也不要求旧 A/B 子树正交。它仍需先通过数值验证，再测完整成本。

再例如，反向拆解 CAKE 找到一种合法、低转换成本的物理组织，另一个 agent 用 H5 的局部数值块去适配它。这是可检验的合成方向，不能提前称为涌现成功。

### 5.4 防止去重再次抹掉新设计

数学式相同，只说明语义相关，不说明物理实现相同。分别记录：

- 语义身份：运算与数值目标；
- 实现身份：布局、分块、指令、存储、同步、源码及编译条件；
- 测量身份：硬件、形状、输入合约、比较对象和计时范围。

物理布局不同的两个候选不能因为旧 IR 丢失字段而被误去重；名字不同但实现相同也不应重复浪费 GPU 时间。去重首先服务于避免重复实验，不是限制思想。

### 5.5 如何分配资源和判断“涌现”

优先测能消除重要不确定性且成本小的方案，同时给高不确定性、新机制方案留机会。不要只保留短期最容易快一点的候选，也不要为每个角色机械均分 GPU。编译/数值便宜探针与完整性能测量分开排队，允许根据结果调整。

记录独立初稿、交换证据、合成新增机制及其结果，才能判断交流是否产生了初稿没有的有效设计。文字新颖、方案可运行、实际提速、多 agent 优于同预算单 agent，是四级不同结论。本次只完成第一轮调研及一次针对流程的交叉批评，未运行新的候选探针，也未验证多 agent 优势。

## 6. 如何测量才能回答原问题

保留三种不同对照，不相互替代：

1. **题目指定的官方 FlashKDA：** 回答迁移后的实际变化。
2. **可构造的匹配 HMMA：** 用相同算法和相近数据流帮助解释 SM100 增量；不能强行塞进不适合它的布局。必要时分别调优，并报告不可匹配处。
3. **已有优化 HMMA：** 说明新方案是否有实际采用价值。即使未胜，也应如实保留相对官方的结果。

先做有限形状的开发实验，再确认到题目官方形状与代表形状。H96 官方形状不能被 H12 替代，H12 也不能被当作整个 KDA；fixed/packed、tail、状态条件要明确。核心比较在 B300/SM103a 上完成，B200 外部结果单列。

微基准回答机制可行性；完整路径回答净收益。若改 K1/K2 分界，就计入两者和新增数据搬运；若改调用方布局，就分别给 kernel 内部与包含转换的成本。使用相同输入和初态、配对顺序、重复测量；有候选后再固定相应确认实验，避免边探索边挑有利口径。

不要求所有研究都服从同一个 2×2。能独立变化时做因子对照；不可分离的联合设计用反向消融、替换和成本分解。未能分离的归因保留为未知，不妨碍报告完整路径的实测收益。

## 7. 下一轮执行顺序

首先开放研究入口，而不是先扩建一个通用编译器。具体协议见 [SM100_OPEN_AGENT_PROTOCOL.md](SM100_OPEN_AGENT_PROTOCOL.md)。旧 Stage9 runner 和 Stage11 预注册继续作为历史实验保留。

建议首批低成本原型是 H1/H2 的共享操作数计算、H3 的数值重写对照、H4 的稳定大块模型，另从 CAKE 做一个可解释的反向消融。这是基于当前证据的起点，不是先完成 P3/P4 才可进入其他方向的排队规则。

数值和合法性检查之后，选择少量不同机制进入 B300 完整成本测量。没有收益同样更新对迁移的判断；只有新证据改变条件时才重开旧失败。最终报告写清值得迁移的实现范围、代价、限制或否定依据，而非为了论文叙事要求一定提速。
