## 用途与当前状态

这是开放研究任务书，可供现有主 agent/子 agent 协作直接使用。它没有替换 `run_stage9_agents.py`，也不表示新 runner、执行适配器或 GPU 实验已经实现。Stage9 的固定语法实验和 Stage11 的 lifecycle × thin-N 预注册仍是各自独立的历史实验；其变量约束不自动进入本协议。

共同事实与候选来源见 [研究报告](SM100_MIGRATION_OPEN_RESEARCH.md)。研究问题只使用标题原文。

用户已明确交付层次：主线回答中要形成带证据的多路径 Typed IR、比较结果与复盘，再开展并发等此前论文中的后续挑战。每个 agent 应留下方案的关键计算/物理选择、源码与证据入口，便于归入路径集合；不要求 idea 提出前先满足旧 IR。多路径结果是本轮正式产物，建设通用框架不是前置任务。已有并发、profile 等结果可作边界或对照，不能替代迁移回答。详见 [最新交接](HANDOFF_SM100_OPEN_RESEARCH.md)。

## 所有 agent 的共同任务

研究 FlashKDA 官方 kernel 当前使用 SM80 MMA，分析迁移到 SM100 是否值得。可以查看官方源码、数学参考、调用方与下游实现、SM100 文档和编译示例；也可以提出需新增 IR 能力的方案。不要将当前实现选择自动视为题目条件，不要预设一定值得或一定不值得。

CHUNK、阶段划分、内部存储、精度、布局、warp/CTA 分工、融合/拆分、部分迁移或整体重写都可以成为研究变量。任何变量变化都必须说明它对同一 KDA 运算、数值、接口和总成本的影响。不会改变 gate/beta 定义或吞掉最终状态来获得性能。改变内部舍入的候选与官方 bitwise 兼容候选分开记录，正确性标准在测量前确定。

自由使用公式、伪代码、源码片段、依赖图和小型原型说明方案。引用应可定位；明确区分官方事实、本地实测、外部报告、推断和新假设。当前 IR 不支持不是算法失败。没有实测不得填写估计为实测性能。

每个有希望的方案说明：改变什么、为什么可能有益、要付出什么成本、什么结果会否定它，以及最便宜的验证方式。若证据指向“不值得”，同样提交可检验的解释。无需凑满固定个数，也无需从已有候选表中选题。

## 首轮独立探索

建议以三个资料入口开始，主 agent 负责证据核对。入口不构成方法禁区，每个 agent 都可以研究任意相关机制。

**入口一：算法与官方源码。** 从 KDA 公式、官方 K1/K2 和 FLA 参考，找出外部语义与实现选择的区别。允许重设求解、分块、舍入、数据流；至少认真考虑一种不能由旧参数树表达的方案。

**入口二：SM100 与可运行实现。** 检查 PTX/CUTLASS/CuTe/Gluon 与已公开 SM100 KDA。可以从官方向前迁移，也可以从已快实现反向移除、替换、消融。不要将软件示例的限制视为整个 ISA 限制，也不要默认文档最新版在本机可用。

**入口三：上下游与完整成本。** 检查谁生产输入、谁消费输出和状态，哪些准备可提前、哪些数据必须落地。提出完整方案或指出微基准隐藏的成本。原问题仍是 FlashKDA 迁移，不把投影算子的独立加速或服务系统优化替代成答案。

首轮保留独立初稿，避免所有人从主 agent 预选的一条方案继续。但首轮不必等到每条 idea 实现完才开始交流。

## 第二轮交叉批评和合成

交换的是可共享的研究产物：事实、引用、公式、代码片段、假设、缺口和实验计划。未验证内容明确标注为假设，不写入已验证事实区。不要求提供私密推理轨迹。

每个 agent 选择另一份最有潜力或最有争议的方案，回答：它在哪个假设上最脆弱；能否从另一份方案借来关键机制；若不能组合，具体依赖或数值冲突是什么。允许重构整个设计，不要求拼接两个补丁或满足子树正交。

主 agent 保留不同的技术路线，而非只挑当前估计最快者。若多个方案只有名称差异，则合并；如果同一数学运算采用不同物理布局或协议，则保留为不同实现。旧 IR 无法编码差异时，以源码/构建参数补足身份，不静默误去重。

## 从 idea 到实验

建议轻量记录以下内容，不要求自然语言初稿提前满足严格 JSON schema：

```text
proposal_id, question
idea, source_refs, assumptions
semantic_effects, numerical_contract
changed_algorithm_or_schedule, expected_benefit, added_cost
cheapest_falsifier, artifact_refs, parent_refs
representation_status: expressible | needs_extension | prototype_first
evidence_status: hypothesis | compiled | correctness_checked | measured
```

对有价值候选再接入编译、正确性和测量。先用现有工具实现最小原型；只有实际缺失的能力才推动 IR 扩展，不先建设全能框架。研究期间允许使用现有主/子 agent 工具和隔离实验目录；GPU 作业由协调者安排，避免并行测量相互干扰，遵守已有工具权限。

不能将 `needs_extension` 当作 `incorrect`；不能将编译失败当作性能负结果；不能将随机 finite 检查当作正确性证明。执行状态与结论成熟度分开。

每次进入 GPU 前还要冻结 Python/native 执行身份：解释器、`sys.path`、关键 module 的
真实 `__file__`、native extension 与依赖 `.py/.cu/.cuh/.h` 哈希、requested/actual route
和 fallback。请求候选却实际运行 fallback 的结果只能作为 diagnostic，不能参与排名。
统一记录工具为 `record_execution_identity.py`。

## 比较与反馈

官方 FlashKDA、可构造的匹配 HMMA、已有优化 HMMA分别提供原题对照、机制解释和实用价值对照。公开其差异，不因难以构造完全匹配版本而伪造因果结论。

先检查语义与数值、编译可行性，再测关键成本，最后测完整路径。改动生产者/消费者的候选计入相应额外工作。新候选不被强迫进入旧 2×2；确定要回答的具体对照问题之后才固定实验条件。历史结果继续按原条件解释。

GPU 名额按信息价值、成本和技术差异分配，同时保留高不确定性方案机会；不要求各角色平均分配，不只保留局部最快者。不要重复无变化的旧失败；改变了真实条件则允许重新检验。

## 对多 agent 的判断

记录独立方案与交流后新增机制，以及其来源。若最终存在可运行父方案，比较合成方案与最好父方案；若只能联合实现，报告联合结果和归因限制。

新 idea 出现不等于性能成功，性能成功也不等于多 agent 优势。后者需另做等总资源的单 agent、独立 best-of-N、交流合成对照。当前优先用多 agent 改善迁移研究；不为证明“涌现”而改变题目、筛掉负结果或预设结论。
