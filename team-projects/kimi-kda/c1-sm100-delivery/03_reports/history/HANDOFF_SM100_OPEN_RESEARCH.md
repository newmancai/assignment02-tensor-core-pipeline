### 两个容易直接落成小探针的例子

H1 的逻辑式：`Sᵀ @ [K_dᵀ | Q_dᵀ]`。C16/D128/V128 时是 `[128,128] @ [128,32]`。先核对代码朝向；这是一个逻辑 GEMM，可能需要多条硬件指令。

### 第五步：形成多路径 Typed IR 结果，写入主线回答

每条路径分开维护“方案表示”和“证据结论”，用明确身份关联：

| 方案表示应覆盖 | 证据结论应覆盖 |

| 数值约定、相对父方案的变化 | 成败解释、证据限制、值得重新尝试的条件 |

这是内容要求，不是强制所有方案套同一个僵硬 schema。复用现有类型；需要时扩展。先通过原型探索的方案，之后应把关键物理选择补入结构化表示。尚未能准确表达的部分保留显式缺口，不把自由文本或不完整字段称为已经验证的完整 Typed IR。

1. 路径对照表：各路径改变什么，属于什么验证/测量范围，结果如何。
2. 关键 IR 差异：用实际字段或计算关系解释布局、指令、生命周期或算法组织的区别。
3. 成败复盘：哪些原先假设得到支持，哪些被证伪，哪些还无法归因。
4. 对原问题的回答：在哪些已测条件下值得或不值得迁移，尚有什么限制。

## 6. 失败时怎么处理

| 遇到情况 | 应做的事 | 不应下的结论 |
|---|---|---|
| 旧 schema 拒绝新布局/融合 | 记录 `needs_ir_extension`，用最小原型或补能力 | “这个算法非法” |
| 当前 nvcc 不支持某语法 | 核对 ISA、架构和工具链，保存错误 | “tcgen05 不值得” |
| 没有 B300 可用 | 继续源码、数值、编译准备，明确未测 | 用 5090 代测并写 B300 结论 |
| correctness 不通过 | 定位公式/布局/同步/舍入差异，修正或结束该候选 | 调宽阈值到通过 |
| 微基准更快但完整链更慢 | 记录转换/准备等成本，判断是否有新机制可消除 | 只报道微基准为总收益 |
| 某方案更慢 | 保存限定条件的负结果，可换独立机制 | 禁止该技术家族的全部方案 |
| 两个父方案无法独立运行 | 记录联合设计与归因限制 | 捏造 2×2 交互数值 |
| agent 给出新名词但机制相同 | 合并重复提案，保留真正物理差异 | 按名字统计“新 idea 数量” |

只重复对解决问题有用的检查。已明确失败且没有真实改动的候选不重复跑；新的数据流、数值表示或实现可以重新提出假设。

## 7. 防止再次偏离题目

- 不将并行度优化替代成迁移问题；它可以是解释变量或候选组成。
- 多路径 Typed IR 与对应证据、结果复盘是本轮主线的正式交付。不要将建设通用 IR 平台、多 agent 框架或重写论文误当作前置任务。
- 先完成迁移的多路径结果与阶段性回答，再开展并发等之前论文的后续挑战；复用旧成果作对照不等于重开那些研究主线。
- 不说“唯一值得研究的是跨阶段 TMEM”；那是旧阶段偏窄的推进判断。

- 不要求所有数学候选 bitwise 复制旧内部舍入；也不忽略官方 bitwise 兼容与算法等价的差别。
- 不预设必须全部换指令。选择性迁移可以回答问题，完整重写也可以研究。
- 不宣称 CAKE 的全部收益属于 tcgen05，或本项目已经复现其端到端服务收益。
- 不宣称这次三个 agent 调研已经证明“涌现”。记录方案来源，待实现、测量后再判断。
- 不先把 H1–H8 改成新的固定枚举白名单。
- 不自动投稿、发消息、提交 PR 或发布结果；本轮授权是研究推进，不包含这些外部行动。

## 8. 每轮结束时留下什么

在实验目录 README 或新状态文件中写七项，保持简短且可操作：

1. 本轮实际改变了什么；
2. 运行了什么命令、在哪台设备、得到什么结果；
3. 哪些结果是事实，哪些仍是假设；
4. 原始日志和源码在哪里；
5. 下一条最有价值的操作是什么；
6. 是否有阻塞，以及还能独立推进什么。
7. 本轮更新了哪条路径的 IR、证据关联和跨路径结论；若表示尚不完整，缺什么。

最终向用户汇报时围绕“迁移是否值得”的证据变化，不以创建了多少文件、多少 agent 或多少 gate 作为主要成果。
